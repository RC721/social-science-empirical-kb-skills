# Correction and Promotion

Record every material human correction with correction ID, item key, artifact, field, error class, old and corrected values, Evidence ID, root cause, affected Skill and version, reusable-rule decision, reviewer, and time.

Do not generalize from one unusual paper. Cluster repeated failures, propose the smallest rule or schema change, and develop it outside the production package. A candidate patch must pass unit tests, the affected gold cases, the full regression suite, and fresh forward tasks before human promotion.

Version Skills, schemas, and runtime independently with semantic versions. Pin published versions and keep a rollback artifact. Production Skills must never rewrite themselves or immediately activate their own candidate patch.
